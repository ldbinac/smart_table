# 开源多维表格SmartTable V1.6.1发布：增加工作流画布可视化配置功能，让工作流配置更直观

v1.6.0 发布的时候，我们给 SmartTable 加了工作流引擎。当时工作流的配置主要是通过表单填字段、选条件，虽然能用，但那种"写程序"的感觉还是比较重。

这次 1.6.1 主要就是让工作流变得更直观——**可以在画布上拖拽、连线、分支，所见即所得**。

## 一、画布编辑：像画流程图一样配置工作流

之前配置一个工作流，大概是这样的：

- 在表单里选触发类型（定时触发？记录创建时触发？）
- 填触发条件
- 一个个添加节点，每个节点填参数
- 如果有条件分支，还得手动维护分支 ID 的对应关系

说实话，配置的时候脑子里得有一个"执行链"的概念，不然容易配错。

现在有了画布编辑，流程变成这样：

- 从左边拖一个节点到画布上
- 拖一条线连到下一个节点
- 双击节点配置参数
- 条件分支拖出多根线，指向不同的下一节点

就像用 draw.io 画流程图一样，但画完就能跑。

## 二、条件分支：看得见，不会乱

条件节点之前有个问题：分支多了容易搞不清楚谁是谁。

现在每个分支都显示在画布上，线上的标签可以写着"金额 > 10000"之类的条件摘要。一眼就能看出哪个分支对应什么条件。

还加了个**默认分支**功能。如果所有条件都不满足，就走默认分支。之前没有这个，遇到非预期情况工作流可能就停那儿了。

## 三、执行日志：出问题能快速定位

工作流跑起来之后，有时候需要看执行过程。比如一个工作流卡住了，想知道是哪个节点出的毛病。

执行日志现在会显示节点名称，而不只是节点 ID。看日志的时候不用再去翻工作流配置，直接能看到"发送通知邮件节点执行失败"这样的信息，排查起来省事很多。

## 四、Webhook：引用之前先检查

如果工作流里有 Webhook 节点，现在会先检查这个 Webhook 配置是不是还存在、是不是有效。之前删了一个 Webhook 配置，引用它的节点还在那儿，执行的时候才报错。

现在提前校验，配置阶段就能发现问题。

## 五、几个问题的修复

顺带修了几个小问题：

- 复制工作流的时候，节点 ID 的引用关系没映射好，导致新工作流跑不了 —— 修了
- 条件分支的执行链生成逻辑有边界情况 —— 修了
- 几个测试用例失败 —— 修了

## 六、怎么用？

1.6.1 已经在 GitHub 和 Gitee 上发布。如果已经在用 1.6.0，拉取最新的一键运行包或docker镜像就行。

新用户可以下载试用，项目开源免费。
